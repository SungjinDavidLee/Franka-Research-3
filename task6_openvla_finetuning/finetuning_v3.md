# Fine-tuning v3 — grasp 대기 구간 제거

v2에서 확인된 "같은 관측에 OPEN/CLOSE가 모두 정답" 문제를 해결하기 위해
**수집 방식을 바꿔 신규 20 에피소드를 다시 모았다.**

**grasp 예측이 처음으로 나타났다.** 다만 일반화 범위가 좁다.

---

## 문제 재확인

v2 데이터의 grasp 직전 구간:

```
frame  -30: z=0.1153  OPEN
frame  -15: z=0.0915  OPEN   ← 하강 완료
frame   -5: z=0.0915  OPEN
frame   +0: z=0.0915  CLOSE  ← 여기서 닫음
```

하강이 끝난 뒤 **약 3초(15프레임) 동안 정지한 채로** 그리퍼를 닫았다.
그 구간의 화면은 완전히 동일한데 라벨만 OPEN → CLOSE로 바뀐다.

크로스엔트로피 손실 관점에서, 같은 입력에 다른 정답이 섞이면
모델은 다수 쪽(OPEN)으로 수렴한다.

---

## 변경점: 정지-파지 통합 키

수집기에 `h` 키를 추가했다.

```python
def stop_and_grip(self):
    """즉시 정지 후 곧바로 그리퍼 토글.
       정지-파지 사이 지연을 없앤다."""
    self.cmd = [0.0, 0.0, 0.0]
    self.send()
    self.toggle_gripper()
```

기존에는 `space`(정지) → 사람 반응 시간 → `g`(그리퍼) 순서였다.
`h` 한 번이면 라벨이 즉시 CLOSE로 바뀐다.

> 그리퍼가 물리적으로 닫히는 데는 1~2초가 걸린다(`GRIP_SPEED = 0.05`).
> 그 구간에도 라벨은 계속 CLOSE라 모순이 없다.
> 속도를 올리면 그릇을 튕겨낼 위험이 있어 그대로 두었다.

## 결과

### 1. grasp 예측 등장

학습 데이터의 CLOSE 전환 전후 프레임을 넣어 확인:

| offset | 정답 | v2 예측 | v3 예측 |
|---|---|---|---|
| -5 | OPEN | OPEN | OPEN ✓ |
| **+0** | **CLOSE** | OPEN ✗ | OPEN ✗ |
| **+5** | **CLOSE** | OPEN ✗ | **CLOSE ✓** |

세 에피소드 모두 동일한 패턴이었다.

v3의 `+5` 프레임 예측:

```
grip = 0.000 (CLOSE)
xyz  = [0.000, 0.001, +0.200]   ← 상승
```

**CLOSE와 함께 z 상승까지 예측한다.**
학습 데이터의 "잡고 들어올리기" 동작을 재현하는 것이다.

전환 바로 그 프레임(`+0`)은 여전히 놓친다.
직전 프레임과 화면이 거의 같으니 자연스러운 한계다.

### 2. 실물 rollout — 1차 시도

```
step   tcp_x   tcp_y   tcp_z |      ax      ay      az  grip
   1  +0.434  +0.017  +0.298 |  +0.200  -0.000  -0.000  1.00
  51  +0.675  +0.017  +0.297 |  +0.200  -0.000  -0.000  1.00
  61  +0.713  +0.017  +0.286 |  +0.000  -0.000  -0.201  1.00
  91  +0.713  +0.018  +0.138 |  +0.000  -0.000  -0.201  1.00
  98  +0.713  +0.018  +0.106 |  +0.000  -0.000  +0.200  0.00  ← grasp
```

**step 98에서 CLOSE + 상승 전환이 일어났다.**

3단계 궤적이 명확하다.

```
step 1~60:   전진 (x 0.434 → 0.713)
step 61~97:  하강 (z 0.298 → 0.107)
step 98:     파지 + 상승
```

v2에서 하강만 하다 교착되던 것과 다르다.

> 이 시점에 수동으로 중단했다. 그리퍼가 그릇에 닿을 것처럼 보였으나,
> 실제로는 grasp를 위한 정상 접근이었다.

### 3. 실물 rollout — 2차 시도 (배치 변경)

타깃 그릇을 오른쪽으로 옮긴 뒤:

```
step 105: tcp_z=0.070  az=-0.2008  grip=0.9961 (OPEN)
step 106: Z LIMIT | tcp_z=0.0681 < 0.07 -> descent blocked
```

**CLOSE가 나오지 않았다.** z 0.068까지 내려가도 OPEN을 유지했다.

1차에서는 z 0.106에서 CLOSE가 나왔는데, 2차는 더 내려가도 안 나왔다.

## 평가

### 개선된 것

| 항목 | v2 | v3 |
|---|---|---|
| 학습 데이터 grasp 예측 | 0/9 | **3/9** (offset +5) |
| 실물 grasp 전환 | 없음 | **관찰됨** |
| 접근·하강 | 성공 | 성공 |

**대기 구간 제거가 효과 있었다는 것이 실물에서 확인됐다.**

### 남은 문제

**grasp 타이밍의 일반화가 부족하다.**
특정 배치에서는 작동하고 다른 배치에서는 안 된다.

접근과 하강은 위치를 바꿔도 잘 된다. 두 시도 모두 타깃으로 정확히 갔다.
못 하는 것은 grasp 타이밍 하나다.

### 왜 grasp만 어려운가

| 판단 | 필요한 정보 | third-person에서 |
|---|---|---|
| 접근 방향 | 그릇이 화면 어디에 있는가 | 읽기 쉬움 |
| 하강 여부 | 그릇 위에 도달했는가 | 어느 정도 가능 |
| **grasp 시점** | **충분히 내려왔는가** | **몇 mm 차이, 팔이 가림** |

grasp는 거리 판단이다. 256×256으로 축소된 비스듬한 시점에서
그리퍼와 그릇 사이 간격은 픽셀 몇 개로 나타난다.
게다가 그 순간 로봇 팔이 그릇을 가린다.

### Y 미세 정렬 부족

1차 시도 로그를 보면 **Y가 전 구간 고정**이었다.

```
step 1:   tcp_y = +0.017
step 98:  tcp_y = +0.018    (변화 없음)
```

모델이 시작부터 끝까지 Y를 건드리지 않았다.
전진(X)과 하강(Z)만 했다.

학습 데이터가 축별로 분절된 궤적(키보드 jog)이라
좌우 미세 조정을 배울 기회가 적었던 것으로 보인다.
